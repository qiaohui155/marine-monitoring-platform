# 油污事件自动预警

## 项目检查与改动边界

当前前端是原生 HTML/CSS/JavaScript，不是 React/Vue；地图为 MapLibre GL JS 5.24.0。主程序中的变量保存船舶、轨迹和油污 GeoJSON，`FloatingPanelManager` 管理已有窗口。后端为 FastAPI + PostgreSQL/PostGIS。

本功能复用地图实例、已有字体/阴影变量和拖动窗口管理器。所有新地图源和图层使用 `oil-alert-` 前缀，不删除或替换原有业务图层、09轨迹查询、11来源筛选或12预警记录。原07风险概览仍保留，新窗口按需求标题显示“07 油污事件自动预警”。07和12工具入口增加未处理数量，12内部增加自动预警列表。

本次没有数据库迁移或写入，没有新增 Python 依赖，也不需要前端构建或安装 npm 包。

## 启动和测试

**直接双击原来的 `start_platform.bat`。** 它复用现有启动流程，打开测试页面并自动触发一条预警，不用另找文件、手动修改网址或寻找03按钮。同一标签页刷新不会再生成测试事件；关闭弹窗后可在12中重新打开。正常业务页面仍可通过不带参数的 `http://127.0.0.1:5173/` 访问。

1. 在项目根目录双击 `start_platform.bat`，沿用原来的启动方式，并自动展示预警测试。已经运行的服务会被复用。
2. 正常页面：`http://127.0.0.1:5173/`，按 Ctrl+F5 刷新。
3. 开发测试页面：`http://127.0.0.1:5173/?devAlerts=1`。
4. 打开左侧 **03 System Status**，滚动到窗口底部的“开发测试 · 油污自动预警”。
5. 选择高/中/低风险，点击“模拟油污预警”。高、中风险打开窗口；低风险只显示右上角通知。测试按钮每次生成一个新ID；“重复发送同一事件”验证去重。
6. 点击右侧候选船，查看船位、事件前后历史轨迹和最近接近点。底部可以查看AIS异常、启动/停止约15秒的时间比例回放、确认预警或下载HTML报告。
7. 标题栏支持拖动、最小化/恢复、关闭。关闭不会撤掉地图事件；地图右下方“打开预警”恢复窗口，“清除预警定位”清除新高亮并恢复普通船舶透明度。
8. 正常页面不显示测试按钮，且使用与开发模式不同的浏览器存储，测试确认和测试未处理数量不会进入正常页面。

测试事件位于穆桑达姆东侧离岸海域，中心为 **56.65°E, 26.35°N**，包含油污多边形、1/3/6小时预测范围和3艘测试船。没有原始影像时显示“范围示意”，不把示意图称为卫星观测。

## 触发与状态规则

- 现有每5秒成功刷新油污数据后，将 GeoJSON 快照交给 `acceptSnapshot()`；首次成功快照只建立旧事件基线，不把已有档案全部弹出。随后出现的新ID才触发预警。刷新失败不建立空基线。
- 已接收ID先登记，再查询候选船；并发请求和重复推送不会重复弹窗。刷新网页保留ID和确认记录，但不自动重播旧弹窗。12列表可以重新打开它们。
- 高/中风险自动打开窗口并定位；低风险只通知，在没有其他完整预警窗口打开时定位，避免低风险事件打断正在查看的高风险事件。风险未提供时仅通知，不假定为高风险。
- 通过已有接口自动筛选事前24小时内、附近10 NM的候选船。接口未提供关联概率时显示“未评估”，不会把空间距离换算成责任概率。
- 默认显示概率最高的前5艘；无概率时按距离排序。真实候选船的当前坐标、速度和航向随已有AIS刷新更新，不改变历史证据点，不自动重新移动地图。
- 默认读取检测前2小时至检测后1小时的历史点（不超过当前时间）。若候选经过时间更早，则向前扩展到该时间前30分钟，最多回溯24小时。查询上限20000点，达到上限显示可能截断。测试船使用夹具内附的轨迹。
- 相邻轨迹点间隔超过10分钟显示红色虚线；它只是缺测端点连接，并非已知航行路线。回放经过缺测区间时隐藏回放船位，不生成假坐标。AIS缺测不等于主动关闭AIS。
- 确认操作目前只修改独立预警记录，不修改数据库油污事件的业务处置状态。保存确认时间；只有已有登录信息时才保存确认人，不把头像“OM”当成已认证用户。
- 去重与确认保存在本机浏览器 `localStorage`。不提供跨设备/跨用户同步。保留未处理记录和最近100条已确认记录摘要；已处理ID保留用于去重。浏览器存储被清理或不可写时不能保证刷新后的持久化，界面会提示存储问题。
- 所有显示时间统一 UTC。`detectedAt` 是检测时间；`releaseTime` 未知时保持空值，不混为实际泄漏时间。

## 真实数据接入

数据结构以 `types.d.ts` 为准。油污几何为WGS84 GeoJSON，时间为带时区的ISO8601，概率和置信度取0～100；未提供的分析字段传 `null`。原始卫星图片使用受控HTTP(S)地址。

### 已经接通的读取路径

- `/api/pollution-events?limit=1000`：利用现有5秒刷新识别新事件ID。
- `/api/pollution-events/{id}/candidate-vessels`：读取事前空间筛选结果。
- `/api/ships/{mmsi}/track`：读取带时间戳的历史点，不使用只有折线、没有每点时间的接口回放。
- `/api/ships`：复用主程序中已经加载的最新船位。

默认候选筛选仍是“事前轨迹与检测到的油污范围”匹配，不包含真实风场/海流回溯模型。界面显示预测范围的能力已完成，但不会从没有输入的风场凭空算出预测。

### 新REST预警服务

在 `source.js` 中替换 `createApiAdapter()` 或在主程序启动前提供 `window.OIL_ALERT_CONFIG.adapter`，实现 `enrich(event)`、`loadTrack(event,vessel)` 和可选 `acknowledge(record,user)`。

独立的增量预警接口可以返回 `{ "events": [OilAlertEvent] }`，模块初始化后调用：

```js
window.oilAlerts.startPolling({
  url: 'http://127.0.0.1:8000/api/oil-alerts', // 待后端提供，并非当前已有接口
  intervalMs: 5000,
  mode: 'events'
});
```

若服务返回完整GeoJSON快照，用 `mode: 'snapshot'`，首次快照会按旧档案基线处理。默认已接现有油污轮询；部署独立服务时应统一事件ID，避免同一个业务事件使用两套ID。

### WebSocket

```js
window.oilAlerts.connectWebSocket('ws://127.0.0.1:8000/ws/oil-alerts'); // 待后端提供
```

支持单个事件对象、`{event: ...}` 或 `{events: [...]}`；重连有退避，重复消息仍经过统一去重。HTTPS部署使用WSS。也可以在启动前设置 `window.OIL_ALERT_CONFIG.webSocketUrl`。认证、补发游标和跨设备确认状态由真实后端负责。

### 后端还需要配合

1. 风场/海流或分析服务产生的1、3、6小时漂移方向、速度和范围；需要溯源时提供回溯结果与不确定性。
2. 原始卫星影像、检测置信度、油污长度/宽度/形态等分析字段。
3. 候选船关联概率及依据、船旗、AIS异常分析；无证据时不得将缺测标成主动关闭AIS。
4. 带身份认证、幂等控制和审计时间的确认写接口；成功后返回 `acknowledgedAt` 和 `acknowledgedBy`。现有FastAPI CORS只允许GET，新增确认接口时要明确放行相应方法并实现权限校验。
5. 跨终端预警未处理数量、重连补发和状态同步。
6. 正式技术/法律报告服务。当前下载的是调查参考HTML报告，含可用记录及数据缺口，不等于已审核证据包。

## 自动测试

```powershell
node --test frontend/tests/*.test.cjs
```

浏览器测试需要可用的Playwright和Chromium/Edge，可通过环境变量 `PLAYWRIGHT_MODULE` 指定Playwright目录，`BROWSER_PATH` 指定浏览器可执行文件：

```powershell
node frontend/tests/auto-alerts.browser.cjs
```

浏览器测试采用独立上下文，覆盖测试按钮、风险分级、去重、确认、刷新、候选轨迹、缺测段、回放、窗口拖动与恢复、清除以及1920×1080、1366×768、1280×720、1024×768、800×600布局。截图输出到系统临时目录，不进入仓库。
